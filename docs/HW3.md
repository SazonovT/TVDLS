# Подготовка AST к HW3

Поддерживаемое подмножество соответствует Funny: переменные `int` и `int[]`,
логические выражения `bool`, функции с одним или несколькими результатами,
формулы, кванторы и все операторы HW2. Типы `string`, переменные `bool`,
функции как значения и перегрузки в этом подмножестве отсутствуют.

## API типов

- `Ast.Type.INT`, `INT_ARRAY`, `BOOL` — типы значений.
- `UNKNOWN` — анализ ещё не выполнен либо тип пока не выведен.
- `ERROR` — при анализе уже обнаружена ошибка; анализатор может использовать
  этот тип, чтобы избежать каскадных сообщений.
- `Ast.Type.tuple(List<Type>)` — два или более результатов вызова функции,
  с сохранением порядка. Сравнение типов — через `equals`, включая кортежи.
  Список элементов неизменяемый и копируется при создании.

Все выражения наследуют `Ast.Expr`: `getInferredType()` и `setInferredType(Type)`.
Это относится также к условиям, формулам и кванторам. Историческое имя `IntExpr`
сохранено как синтаксическая категория: переменная или вызов в этой категории
может иметь тип массива; вызов в кортежном присваивании — тип кортежа.

У `VariableDef` исходная аннотация хранится в `getDeclaredType()` и не меняется
при выводе типов. При отсутствии аннотации это `UNKNOWN`.
`hasTypeAnnotation()` отличает явно типизированное объявление от локальной
переменной без типа. `setInferredType()` сохраняет результат анализа,
`getType()` возвращает исходный тип, если он указан, иначе выведенный.
Это позволяет отдельно диагностировать конфликт аннотации и выведенного типа.

Парсер устанавливает только исходные типы объявлений. Типы выражений после
разбора равны `UNKNOWN`: даже литералы пока не прошли семантический анализ.
После аннотирования тот же `MermaidAstPrinter` выводит типы выражений и
эффективные типы объявлений, параметры формул и цели кортежных присваиваний.
Позиции узлов (`getLine()`, `getColumn()`) по-прежнему отсчитываются от нуля.

## Семантический анализ HW3

`SemanticAnalyzer` выполняет отдельный проход после парсера. Сначала он собирает
сигнатуры всех функций и формул, затем проверяет их тела. Поэтому рекурсия и
вызовы определений, расположенных ниже, разрешены. Имя `length` зарезервировано
для встроенной функции `(int[]) -> int`.

```java
SemanticAnalyzer analyzer = new SemanticAnalyzer();
List<SemanticAnalyzer.Diagnostic> errors = analyzer.analyze(module);
String annotatedAst = new MermaidAstPrinter().toMermaid(module);
```

`analyze` изменяет аннотации переданного AST и возвращает неизменяемый снимок
диагностик. `getDiagnostics()` возвращает такой же снимок последнего запуска.
Повторный запуск очищает ошибки и заново вычисляет типы. Анализировать следует
дерево без синтаксических ошибок. `Main` вызывает анализатор после успешного
парсинга и выводит аннотированный AST. Семантические ошибки печатаются в `stderr`;
AST при этом сохраняется, а процесс завершается с кодом 1. При синтаксических
ошибках семантический анализ и генерация Mermaid не выполняются.

Проверки:

- Неизвестные имена, повторные определения, дубликаты переменных и кванторов.
- В `requires` видны только параметры; в `ensures` — параметры и результаты;
  в теле и инвариантах — также локальные. Переменные кванторов ограничены телом
  квантора и не могут повторять видимое имя переменной.
- Параметры доступны только для чтения, включая обновление элементов массивов.
- Арифметика, сравнения и индексы требуют `int`; логические операции — `bool`.
  Неявных преобразований и сравнения массивов нет.
- Проверяются вид вызываемого определения (функция/формула), число и типы
  аргументов. Несколько результатов разрешены только в кортежном присваивании;
  число и типы целей должны совпадать. Повторные цели диагностируются.
- Тип локальной без аннотации выводится по первому корректному присваиванию
  при обходе исходного текста. Корректное `a[i] = value` позволяет вывести
  `a: int[]`. Некорректное присваивание не фиксирует тип. Противоречия,
  чтение до вывода типа и оставшиеся неизвестные типы диагностируются.

Объявления `uses` действуют во всей функции; блоки не вводят объявления.
Ветки и циклы обходятся в порядке текста, без анализа достижимости и определённой
инициализации. Для переменной с известным типом чтение до присваивания не
диагностируется: по спецификации результат такого чтения неопределён.
Проверка истинности контрактов, деления на ноль и границ массива относится
к следующим этапам. Многомерные обращения из синтаксического теста `Indices`
отклоняются, поскольку поддерживается только `int[]`.

Каждое посещённое выражение получает тип, включая `ERROR` при ошибке.
Ошибочный дочерний узел не порождает повторного сообщения о несовместимости
в родителе; независимые ошибки продолжают накапливаться.

## Проверка (из корня проекта, Java 21)

```powershell
javac -encoding UTF-8 -d out src/*.java tests/*.java
java -cp out AstTypesTest
java -cp out SemanticAnalyzerTest
java -cp out Main in/test.funny -o in/out.mmd
```

`AstTypesTest` проверяет API типов и вывод дерева. `SemanticAnalyzerTest`
содержит положительные и отрицательные программы с ожидаемыми сообщениями,
проверяет аннотации, позиции, накопление ошибок и повторный запуск анализа.
Для `../in/test.funny` ожидаются только две ошибки многомерного доступа в `Indices`.
